It was some 3-odd years ago when I was unpacking a threat hunt on Wireshark and came across an odd packet — an easter egg, a DCOM-hole over a socket with hex that translated to “Meow”. The Meow Packet. Down the rabbit hole we went to get my cat back, with a BLASTER RPC and a CVE from 2003.

The Meow Packet. The four bytes 4d 45 4f 57 — “MEOW” — prefix every object reference marshalled over MSRPC/DCOM. In 2003 that marker rode an ISystemActivator bind on TCP 135 into a UNC-path buffer overflow behind a 0x90 NOP sled: CVE-2003-0352 / MS03-026, the hole the Blaster worm wore. For a hunter it’s a gift — the MEOW prefix, the GUID, and the sled are exactly the fingerprints you key a detection on. NFR’s rapid-response writeup →

01 — the terrain

How a machine wakes up

Power hits the CPU and it runs firmware, which hands off stage by stage until an OS is in control. Each handoff is a place code can be swapped. Pick a path and tap a stage.

02 — the instrument

ChainLoader / BootKitStudio

A defensive simulator. It never writes a boot sector or firmware — it models each stage as a marker, runs a VM under hard guardrails, and emits JSON evidence a SOC can read. The core loop is four steps, and it fails closed if any safety gate is missing.

Guardrails (fail-closed)

  • BKS_LAB_MODE=1 required
  • VM image under lab/vms only
  • reject /dev/* physical disks
  • snapshot · rollback · evidence preconditions
  • base image never written (overlay only)

03 — the first instruction

10biForthOS — a Forth in 512 bytes

The smallest honest version of the whole chain: one boot sector that is a working Forth. It fits in the 512 bytes BIOS loads, ending in the 0x55AA signature. It speaks a two-byte protocol over the serial line — 0x01 <byte> compiles one byte; 0x00 runs what you compiled.
